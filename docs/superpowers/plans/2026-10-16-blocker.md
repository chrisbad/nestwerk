# Blocker – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (nativ, ohne Subagenten – Nutzerwunsch).

**Goal:** Arbeits-, Schlaf-, Ruhe- und Freizeiten als Blocker, die beim Einplanen geprüft werden, Ruhe schützen und den Haushaltsplaner auf Uhrzeiten heben.

**Architecture:** Paket `blocker` (Modell, Feiertage, Expansion zu Zeitfenstern, Konfliktprüfung, Ruhe-Ziele). Der `CalendarEventService` erzwingt Sperren, Controller/JS/MCP/Import zeigen Warnungen. `DeliveryWorker` fragt den Ruhe-Modus ab. `ChorePlanner` nutzt eine Verfügbarkeitsabfrage statt nur Abwesenheiten.

**Tech Stack:** Spring Boot 4.1, JPA, Flyway, Thymeleaf/htmx, Vanilla-JS (Eclipse-Stil), Testcontainers.

**Spec:** `docs/superpowers/specs/2026-10-16-blocker-design.md`

## Global Constraints
- Migration `V20__blockers.sql`. Zeiten in `CalendarSettings.zone()`.
- Arten `WORK, SLEEP, REST, LEISURE, CUSTOM`; Stärken `SHOW, WARN, BLOCK`; Sichtbarkeit `TITLE, BUSY, HIDDEN`.
- Serienprüfung 8 Wochen; Alternativen: max. 3, 7–21 Uhr, heute + 6 Tage.
- Standardfenster Hausarbeit 07:00 bis Fälligkeit bzw. 21:00; Dauer = `minutesMedium`.
- Rechte: Kalenderrechte wiederverwenden.
- Texte deutsch, UI im Eclipse-Stil, mobil benutzbar.

## Review Focus
- Blocker über Mitternacht (22:00–06:30) an Monatsgrenze und Zeitumstellung → richtige Instants. (Task 3)
- Termin ohne Personen → nie Konflikt. (Task 5)
- Handelnder ist selbst betroffen → nie gesperrt. (Task 5)
- Ganztägiger Termin gegen Blocker → zählt als ganzer Tag. (Task 5)
- Sichtbarkeit HIDDEN → fremde Nutzer sehen weder Band noch Titel, auch nicht über Konflikttexte (dann „ist nicht verfügbar“). (Task 5, 7)
