# Updates aus der App – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> In diesem Projekt: nativ, ohne Subagenten (Nutzerwunsch).

**Goal:** Admins sehen neue Versionen in Nestwerk und spielen sie mit einem Klick ein; schlägt das fehl, läuft die alte Version mit den alten Daten weiter.

**Architecture:** Paket `update` in der App (Versionsprüfung über GitHub, Aufträge als Dateien in einem gemeinsamen Volume, Verlauf in `update_runs`). Ein eigener `updater`-Container (docker:cli + Bash) mit Docker-Socket arbeitet die Aufträge ab: Sicherung → Dateien tauschen → Pull → Start → bei Fehler Rückfall inkl. Restore.

**Tech Stack:** Spring Boot 4.1, Thymeleaf/htmx, Flyway, RestClient, Testcontainers; Bash, Docker Compose ≥ 2.24.

**Spec:** `docs/superpowers/specs/2026-10-16-updates-design.md`

## Global Constraints
- Kanäle `RELEASES` (Standard) und `MAIN`. Image-Tags: `X.Y.Z` bzw. `sha-<sha7>`; laufende Version `X.Y.Z` bzw. `0.0.0-<sha7>`; `dev` = keine Prüfung.
- Prüfintervall 6 Stunden. Warten auf Gesundheit: `--wait-timeout 300`.
- Auftragsverzeichnis App `/data/updater`, Updater `/work`; Struktur `jobs/<id>/{request.json,files/,ready,status.json,log.txt,backup,previous/}`.
- Zustände: `QUEUED`, `RUNNING`, `DONE`, `ROLLED_BACK`, `FAILED`. Schritte: `BACKUP`, `FILES`, `PULL`, `START`, `ROLLBACK`.
- Recht `UPDATE_MANAGE` (Modul „Verwaltung“, Label „Updates verwalten“). Benachrichtigungstypen `UPDATE_AVAILABLE`, `UPDATE_DONE`, `UPDATE_FAILED`.
- Die App bekommt keinen Docker-Socket. `.env` ändert der Updater nur bei `NESTWERK_VERSION`.
- Texte deutsch, Code-Stil wie im Paket `backup`.

## Review Focus
- GitHub nicht erreichbar / Token falsch / Repo privat ohne Token → Prüfung meldet verständlichen Fehler auf der Admin-Seite, kein Stacktrace, Scheduler läuft weiter. (Task 4)
- Zweiter Klick auf „Aktualisieren“, während ein Auftrag läuft → abgelehnt mit Meldung. (Task 5)
- Updater nicht installiert (lokal, alte Installation) → Seite zeigt Hinweis, Knopf deaktiviert. (Task 6)
- Status-Datei kaputt/halb geschrieben → als „läuft“ bzw. unbekannt behandelt, keine Exception. (Task 5)
- Laufende Version `dev` oder unbekanntes Format → keine Update-Meldung. (Task 3)

### Task 7: Updater-Container, Compose, Skripte, Workflow

**Files:**
- Create: `updater/Dockerfile`, `updater/updater.sh`
- Modify: `compose.prod.yaml`, `Dockerfile` (`/data/updater` anlegen), `install.sh`, `update.sh`, `.env.example`, `proxy/nestwerk-vhost.conf`, `.github/workflows/release.yml`

**Interfaces:**
- Consumes: Dateistruktur aus Task 5, Befehle aus Task 1.
- `compose.prod.yaml`: Volume `updater` in `app` (`/data/updater`) und Dienst `updater` (`image: ghcr.io/chrisbad/nestwerk-updater:${NESTWERK_VERSION:-latest}`, `restart: unless-stopped`, Volumes `/var/run/docker.sock`, `${NESTWERK_DIR:?…}:${NESTWERK_DIR}`, `${DOCKER_CONFIG_DIR:-/root/.docker}:/root/.docker:ro`, `updater:/work`, `environment: NESTWERK_DIR`, `working_dir: ${NESTWERK_DIR}`).
- `updater.sh`: Schleife alle 5 s: `touch /work/updater.alive`; offene Aufträge mit `ready` ohne `status.json` abarbeiten; beim Start `RUNNING`-Aufträge als `FAILED` („Updater wurde unterbrochen“) markieren. Status per `jq` atomar (tmp + mv). Ablauf exakt wie Spec (Schritte BACKUP, FILES, PULL, START; Fehler → ROLLBACK). Flyway-Stand: `docker compose exec -T db psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -tAc "select coalesce(max(installed_rank),0) from flyway_schema_history"`.
- Workflow: metadata-action zusätzlich `type=sha,prefix=sha-,format=short`; zweiter Build für `updater/` mit gleichen Tags (`ghcr.io/chrisbad/nestwerk-updater`); Job `shellcheck` für `install.sh update.sh updater/updater.sh`; Paket enthält weiter `update.sh` und Compose-Dateien.
- `install.sh`: `NESTWERK_DIR=$INSTALL_DIR` in `.env`, `docker compose pull app updater`. `update.sh`: Zielversion → Compose-Dateien + `update.sh` dieser Version holen (wie `fetch` in install.sh, mit `GITHUB_TOKEN` falls gesetzt), `NESTWERK_DIR` ergänzen, falls fehlend; Pull `app updater`.
- vhost: `error_page 502 503 504 = @nestwerk_wartung; location @nestwerk_wartung { default_type text/html; return 503 '<!doctype html>…Nestwerk wird aktualisiert…<meta http-equiv="refresh" content="5">…'; }`.

- [ ] `shellcheck` lokal (Docker: `koalaman/shellcheck`) auf allen drei Skripten ohne Befund.
- [ ] `docker compose -f compose.prod.yaml config` mit Beispiel-.env gültig.
